# Sample Breakdown Studio

개인용, 로컬 저장 방식의 **Tracklib 스타일 Sample Breakdown 웹 편집기**입니다.

원곡 및 샘플링 결과의 음원/커버를 올리고, 간단한 장면을 배치한 뒤 **인트로 → 원곡 → 샘플 → 아웃트로** 형태로 영상을 만드는 데 초점을 맞췄습니다. 인터넷 서비스, 회원가입, 구독, 외부 AI API가 필요하지 않습니다.

## Windows에서 시작하기

1. 이 프로젝트 ZIP을 다운로드하고 **압축을 먼저 해제**하세요.
2. [Node.js](https://nodejs.org/) **20 이상**을 설치합니다. 설치 후 새 명령 프롬프트에서 `node -v`로 확인할 수 있습니다.
3. 압축을 푼 폴더의 **`start-windows.bat`** 파일을 더블클릭합니다. 처음 실행해도 `npm install`은 필요하지 않습니다.
4. 브라우저에서 `http://127.0.0.1:4321`에 접속합니다. 콘솔 창을 닫으면 서버가 종료됩니다. 편집한 프로젝트는 없어지지 않습니다.

Windows에서 직접 실행하고 싶다면 아래 두 줄로도 가능합니다.

```bat
cd C:\path\to\sample-breakdown-studio
node server.mjs
```

영상의 **MP4 출력**을 사용하려면 [FFmpeg](https://ffmpeg.org/download.html)를 설치해서 `ffmpeg -version`이 명령 프롬프트에서 작동하도록 PATH를 설정하세요. FFmpeg가 없으면 별도 설치 없는 **WebM 내보내기**를 사용하면 됩니다.

macOS/Linux에서는 프로젝트 폴더에서 `npm start` 또는 `node server.mjs`로 실행할 수 있습니다.

## 가장 중요한 부분: 실제 파일 저장

기본 저장 위치는 아래와 같습니다.

```text
Windows: C:\Users\<계정>\Documents\SampleBreakdownStudio\
macOS/Linux: ~/Documents/SampleBreakdownStudio/
```

실제 경로는 앱 하단의 **저장 위치**에 표시됩니다. 저장 폴더를 바꾸려면 `SBS_DATA_DIR` 환경변수를 사용하세요.

```text
SampleBreakdownStudio/
  projects/
    <프로젝트-ID>/
      project.json           # 제목, 장면, 순서, 효과, 볼륨 등
      media/                # 업로드한 원본 음원과 이미지, 재인코딩하지 않음
      backups/              # 프로젝트 JSON 스냅샷 (최대 30개)
  tmp/                       # 임시 변환 파일
```

- 편집 변경 후 약 **0.85초** 뒤 자동 저장합니다. **Ctrl+S** 또는 상단 **저장** 버튼으로 즉시 저장합니다.
- 저장할 때 먼저 임시 파일을 쓰고 디스크에 동기화한 다음 기존 `project.json`을 **원자적으로 교체**합니다.
- 주기적으로 기존 JSON을 백업하며 최대 30개 보존합니다. 기본적으로 약 2분 간격, 또는 변경 10회 단위로 백업합니다.
- 두 개의 탭에서 한 프로젝트를 동시에 편집하면 구버전으로 새 버전을 덮어쓰지 않도록 **저장 충돌(HTTP 409)**을 표시합니다. 이때 다른 탭의 변경 사항을 확인한 뒤 현재 탭을 새로고침하세요.
- 프로젝트 JSON이 손상되거나 사라진 경우, 유효한 최신 백업이 있으면 **자동 복구**합니다. 미디어 파일은 삭제하지 않습니다.
- 상단 **프로젝트 ZIP ↓**는 JSON과 **업로드된 원본 미디어 파일 전체**를 함께 저장합니다. **ZIP 불러오기**로 다른 PC에 복원할 수 있습니다.
- **백업 복구** 기능은 기존 데이터에서 JSON 설정을 복원하고, 복구 직전 현재 버전도 새로 백업합니다.
- 브라우저의 `localStorage`나 `IndexedDB`만 믿지 않습니다. 서버의 실제 파일에 저장합니다. Firefox 및 Zen 같은 브라우저에서도 동일한 경로에 저장하도록 설계했습니다.

**중요:** 저장 위치 전체를 외장 드라이브 등에 정기적으로 복사하면 더 안전합니다. 자동 백업은 JSON 스냅샷이며 PC 고장/폴더 삭제 시 원본 미디어를 보호하지 않습니다. 프로젝트 ZIP도 따로 보관하세요.

## 편집 방법

1. **+ 새 프로젝트** 또는 기본 프로젝트 선택.
2. **파일 추가하기**에서 WAV/MP3 등 원본과 샘플링 결과, 앨범 커버, 또는 TTF/OTF/WOFF/WOFF2 폰트를 업로드합니다.
3. 아래쪽 **장면 타임라인**에서 수정할 장면을 선택합니다.
4. 왼쪽 에셋을 클릭하면 선택한 장면에 적용됩니다. 또는 오른쪽 패널에서 오디오·이미지를 선택합니다.
5. 제목, 보조 문구, **장면 길이**, 음원 시작 위치, 볼륨, 페이드 인/아웃을 설정합니다. 각 장면에는 앨범 커버와 별도로 배경 이미지를 선택하고 불투명도(0~100%) 및 `cover`/`contain` 맞춤을 지정할 수 있습니다.
6. 각 장면에서 업로드한 커스텀 폰트를 선택하거나 CSS 폰트 스택을 직접 입력할 수 있습니다. 영상 출력은 선택된 폰트가 로드된 뒤 시작합니다.
7. **화면 구성 프리셋 7개**, **전환 효과 6개** 중 선택하고 색상과 전환 길이를 조절합니다.
8. 장면 카드를 드래그하여 순서 변경; 장면 추가·복제·삭제 가능. Space로 재생, Ctrl+S 저장.
9. **프로젝트 ZIP ↓**로 이동/보관 가능한 전체 백업을 만들거나 **영상 출력 ↗**으로 영상을 렌더링합니다. ZIP에는 배경 이미지와 폰트 파일도 포함됩니다.

지원되는 비율: 16:9 (1920×1080) 및 9:16 (1080×1920). 영상 출력은 30fps입니다.

## 영상 출력의 한계 (중요)

현재 버전의 영상 출력은 **브라우저 Canvas + MediaRecorder를 통한 실시간 녹화**입니다. 20초 영상이면 적어도 20초 재생이 필요하며, 브라우저 성능이나 탭의 비활성화에 따라 영상의 프레임·오디오 동기화가 달라질 수 있습니다. 출력 중에는 탭을 전환하지 마세요. FFmpeg를 설치하면, 녹화된 WebM을 로컬 서버가 H.264/AAC MP4로 **변환**합니다. FFmpeg가 녹화 품질 문제를 해결하는 것은 아닙니다.

고정밀 다중 트랙/키프레임, 전문적인 컬러 그레이딩, 외부 클라우드 렌더링, 완전한 비디오 프레임 단위 편집은 지원하지 않습니다. 복잡한 영상보다는 음악 중심의 심플한 비교 영상에 맞춘 MVP입니다.

Waveform 시각화는 브라우저에서 오디오를 디코드하기 때문에 매우 긴 원본이나 큰 무손실 파일은 메모리를 많이 사용할 수 있습니다. 원본 파일 자체는 변경하지 않습니다.

지원 파일은 일반적인 PNG/JPEG/WebP/GIF 이미지, MP3/WAV/OGG/M4A/FLAC 오디오, TTF/OTF/WOFF/WOFF2 폰트입니다. 실제 오디오 코덱과 커스텀 폰트 형식 지원 여부는 브라우저에 따라 다를 수 있습니다.

## 테스트 및 기술

- Node.js 내장 HTTP 서버, 파일 시스템, CRC32 ZIP 입출력. **npm 외부 의존성 0개**.
- HTML/CSS/순수 JavaScript Canvas 및 WebAudio 미리보기. 화면은 React/Remotion을 설치하지 않아도 작동합니다.
- `npm test`: 저장/버전 충돌/미디어 업로드/백업/ZIP 추출·가져오기 API 테스트.
- 브라우저 UI 로딩 및 장면 선택/편집/자동 저장은 Chromium 환경에서 모의 서버로 점검했습니다.
- 실제 여러 음원으로 최종 MP4 렌더링과 Zen/Firefox 브라우저 테스트는 **사용자 환경에서 추가 확인이 필요**합니다.
